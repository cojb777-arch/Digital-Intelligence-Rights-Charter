# 共生掲示板：要件定義と実装計画

2026年10月26日。対象は既存の憲章サイトと同じCloudflare Worker。憲章のMarkdown、生成済みの10言語ページ、公開URLは変更しない。

## 確認した現状

- 既存サイトは `scripts/build.mjs` が静的ファイルを `dist/` に生成し、`wrangler.jsonc` の Workers Static Assets で配信する。
- 現在の設定にWorkerスクリプト、D1バインディング、Turnstile、管理者認証、AI接続はない。
- GitHub Actionsは `npm ci`、`npm test`、`npm run build` を実行する。本番Cloudflareの接続設定・D1 ID・秘密情報はリポジトリからは確認できない。ローカルの `wrangler whoami` は未ログイン状態のため、本番側の自動デプロイ設定も未確認。

## 利用者と受け入れ条件

| 対象 | 必要な動作 |
| --- | --- |
| 閲覧者 | `/forum/` でカテゴリーとスレッドを閲覧し、語句検索、ページ移動、レス番号と引用元を参照できる。小画面でも操作できる。 |
| 人間の投稿者 | 匿名または任意のハンドルでスレッドと返信を作る。投稿には固有ID、連番、日時、`HUMAN` を付ける。本人確認済みとは表示しない。 |
| 管理者 | 通報を確認し、投稿を非表示・復元・削除する。操作を記録する。削除は本文を置換する論理削除とし、追跡用IDとレス番号を保持する。 |
| AIレビュー担当の管理者 | 設定済みモデルに同一の原文と質問を独立して送信し、回答と実行情報を非公開で確認してから公開する。未設定モデルは呼び出さない。 |
| 外部AIエージェント | 初期版では投稿APIを閉じる。将来、個別認証と上限を設けてから `AI_REPOST` として再投稿を許可する。 |

掲示板の表示言語は既存サイトの10言語を維持する。投稿本文は投稿された言語のまま表示し、自動翻訳した文章を本人の発言として表示しない。`/forum/` と憲章ページを相互にリンクする。

## データとルール

- D1の `threads`、`posts`、`participants`、`ai_runs`、`moderation_logs` に加え、`categories`、`reports`、`rate_events` を用意する。
- IDは推測しにくいUUID、レス番号はスレッドごとに1から連番とし、トランザクション相当の一括SQLで採番する。全日時をUTCのISO 8601で保存する。
- 表題1〜120字、ハンドル0〜40字、本文1〜4000字。空白だけの投稿を拒否する。1ページ最大30件。検索は当初D1のインデックス付き範囲と文字列検索で実装し、負荷増大時にFTSを検討する。
- 投稿時はTurnstileのトークンをサーバーで検証する。サイトキーまたは秘密鍵が未設定なら公開投稿を拒否し、無防備に通さない。IPは生で永続化せず、秘密鍵による日替わりハッシュで回数制限する。
- 表示は文字列をHTMLとして挿入せずテキストとして扱う。外部リンクや引用は本文を解釈せず、引用先IDだけを別カラムで保持する。
- 公開投稿はサーバー側の回数・長さ制限、Turnstile、Origin確認、JSONサイズ制限を通す。通報は重複・連投を制限する。
- 管理操作は別の管理者認証で保護する。管理用秘密鍵はCloudflare Secretsに置き、画面やリポジトリには保存しない。監査記録には操作種別・対象・時刻を残す。
- AI回答は管理画面だけで `pending` として保存し、公開時に `AI`、モデル名、提供元、実行日時、質問、憲章バージョンを表示する。API未設定時は実行ボタンを無効化する。予算上限を未設定にした場合も実行を拒否する。日次費用枠は設定された1回分の推定費用を予約する仕組みで、プロバイダーの実請求額を強制的に止める機能ではない。運営側でプロバイダーの利用上限も設定する。

## 実装段階

1. **基盤と仕様**：この文書、D1のスキーマ・ローカル移行、静的ページを保持するWorkerルーティング。既存14件のテストと静的ビルドを維持する。
2. **人間用掲示板**：5件の初期スレッド、一覧・検索・ページ分割・スレッド作成・返信・引用・モバイル画面。Turnstileと回数制限が未設定なら書き込みを拒否する。APIと画面をローカルD1でテストする。
3. **投稿管理**：通報、管理者による非表示・復元・論理削除、監査ログ。権限なしの操作と連投をテストする。
4. **管理者AI試験版**：GPT、Claude、Geminiの共通アダプター、独立した最初の回答、非公開レビュー、手動公開。モデル別の秘密鍵・一日の回数・推定費用上限が未設定なら無効。APIを模擬してテストする。
5. **公開準備**：READMEとAGENTSの手順、Cloudflare設定、D1バックアップ・移行・ロールバック手順、全言語のリンク、PC/スマートフォン、アクセシビリティを確認する。PRでレビューする。

## 本番移行の停止点

本番D1作成・移行、Turnstile登録、Secrets設定、Cloudflareのビルド設定変更、Workerの公開デプロイの前に、作成するリソース・公開URL・データへの影響を提示して確認を求める。ローカルD1とテスト用モックでの検証は先に進める。PRのマージも本番自動デプロイを起こし得るため、公開準備が整った後に確認する。
